# 3차 독립 검토: 실제 자료·보안·성능·전체 파이프라인

검토자는 엔진·데이터·대시보드·검증 오케스트레이터 작성자와 분리된 세 번째 검토 역할이다. 전체 소스, 입력 경계, HTTP 응답, 인증과 최종 독립기간 관리, 실제 수집 영수증을 확인하고 결함을 각 작성자에게 재현 조건과 함께 전달했다. 합성 테스트의 통과와 실제 전략의 수익성은 구분한다.

## 발견 사항과 조치

| 항목 | 재현·위험 | 수정과 확인 |
| --- | --- | --- |
| S1 | 보고서 JSON의 `NaN`/`Infinity`를 읽은 뒤 HTTP 직렬화에서 예외가 발생하여 응답이 끊겼다. 과도한 중첩도 처리되지 않았다. | 엄격한 유한수·중첩 검사, 실패 시 503과 투자하지 않음 상태로 처리하도록 수정했다. 실제 HTTP 회귀검사를 실행한다. |
| S2 | 초기 화면은 `engine_verified=true`만으로 실제 자료 증거가 없는 보고서의 PASS를 표시할 수 있었다. | 엄격한 boolean, `data_evidence_verified=true`, 합성 여부를 함께 확인한다. 현 버전의 실제 자료는 자동 합격할 수 없다. |
| S3 | 고정된 `report.json`이어도 심볼릭 링크를 따르면 보고서 경로 밖의 JSON이 노출될 수 있었다. | 보고서 및 `latest` 심볼릭 링크를 거부한다. 임의 경로·인코딩 경로·쓰기 요청도 HTTP 경계에서 거부한다. |
| S4 | `manifest.json=[]`는 명시적 데이터 오류 대신 `AttributeError`를 일으켰다. 파일별 제한만 있어 입력 전체 크기는 제한되지 않았다. | JSON 객체·중첩 검증, 최대 파일 수와 총 바이트 제한을 추가했다. HTTPS 리디렉션도 같은 호스트의 443 포트로 제한한다. |
| S5 | 환율이 없는 USD 자료를 엔진에 넘기면 결과 보고서를 만들지 못할 수 있었다. | 환율 결측이면 성과 계산과 최종기간 개봉을 중단하고 DATA_INSUFFICIENT 보고서를 만든다. 환율을 1로 대체하지 않는다. |
| S6 | 인증/코드 식별자에 오케스트레이터·수집기 변경이 포함되지 않았고, 기존 결과 재사용 시 현재 인증을 확인하지 않았다. | 데이터·검증·CLI 파일을 해시 범위에 포함하고 현재 인증이 무효이면 보관된 원본은 유지하면서 출력 상태를 낮춘다. |
| S7 | 정책의 NaN·비정수 표본 수와 빈 시장 국면 목록을 초기 검사에서 허용했다. | 유한수·정수·허용 범위·필수 시장 국면을 실행 전에 검사한다. 정책과 후보는 성과를 보기 전에 고정한다. |
| S8 | 화면이 실제 보고서 필드와 달라 시장 국면 손익·실행한 단계·신뢰수준을 제대로 표시하지 못했다. | 실제 `realized_pnl`/`expectancy`, `executed`, `alpha`, 코드/정책 해시 계약에 맞췄다. 95%를 임의 표시하지 않는다. |
| S9 (미해결) | 기본 `market_filter=true`는 신호 당시 국면이 `bear`인 신규 진입을 모두 취소한다. 완결 거래의 `regime`도 신호 당시 값을 유지하므로 기본 후보에서는 `bear` 거래가 구조적으로 생기지 않는다. 그런데 정책은 `bear` 거래를 단기 10개·장기 5개 이상 요구한다. 이는 관측 표본 부족을 넘어 현재 설정 사이의 논리적 불일치다. | 결과 확인 뒤 코드·정책을 바꾸지 않았다. 현재 출시판은 이 설정으로 합격할 수 없다. 다음 연구에서는 미사용 자료를 보기 전에 하락장 현금 비중·노출·국면별 순자산 성과를 평가하는 기준 또는 시장 필터 변형을 사전 등록하여 검증한다. 관측 수익률에 맞춰 합격 기준을 완화하지 않는다. |

## 보안 범위

데이터 수집 URL은 명시한 HTTPS 제공처로 제한되며 TLS/체크섬 검증을 끄지 않는다. CSV 입력에 코드 실행·pickle·동적 import 경로는 없고, HTTP는 고정 정적 자산과 결과 JSON 읽기만 제공한다. 보고서 문자열은 HTML 삽입 대신 `textContent`로 표시하고 외부 스크립트·폰트·분석 도구를 사용하지 않는다. 기본 바인딩은 loopback이고 CSP·nosniff·프레임 거부·no-store 헤더를 설정한다. 실전 주문 모듈, 계좌 연결, 키 입력, 실전 활성화 경로는 없다.

이는 인증·권한·트래픽 제한을 갖춘 인터넷 공개 서비스의 보안 인증이 아니다. 공개 배포와 모바일 외부 접속은 별도 운영 설정이 필요하다. 로컬 인증서는 실행 테스트와 파일 해시의 일치 증거이며 전자서명·신뢰기관 인증은 아니다. 로컬 파일을 고의로 조작할 수 있는 연구자를 막지 않는다. 별도 체결 원장 감사는 기록된 수수료·세금 자체를 사실로 받아 현금·재고·손익·성과를 재구성한다. 비용모형으로부터 수수료를 독립적으로 생성하거나 원본 호가에서 슬리피지를 재현하는 별도 oracle은 아니며, 비용·환율 산식은 사람이 계산한 예제와 엔진 테스트로 따로 검증한다.

## 성능 검사

자체 생성한 **가상 데이터** 2종목 × 2,600거래일(가격 5,200봉)로 각 전략을 한 번씩 실행했다. A 2.134초, B 2.512초, C 5.772초, D 1.120초, E 1.205초, F 2.257초였고 프로세스 최대 RSS는 약 22.2 MiB였다. 모든 결과에 별도 체결 원장 감사를 적용하여 통과했다. D/E/F의 거래 0은 필요한 가상 재무/업종 입력이 없기 때문이며 전략 수익성 결론이 아니다. 이 측정은 검토 중간 버전의 대표 단일 실행이며 최종 버전의 성능 보증이 아니다.

대규모 전 종목·분봉·다수 사용자 부하는 실행하지 않았다. 전략의 전체 이력 복사와 RSI 재계산은 자료가 커질수록 비용이 증가한다. 부트스트랩은 순환 블록과 누적합을 사용하며 후보 수를 반영한 꼬리 해상도를 확인한다. 긴 보유기간의 자료 부족은 비싼 전체 그리드 실행을 생략하고 부족으로 기록한다.

## 실제 시장 자료와 최종 재검증

초기 네트워크 시도는 403이었으나, 환경 변경 후 실제 Yahoo/FRED 응답을 확보했다. 독립 검토에서 `data/real-yahoo/collection.json`, 원본 `raw/000.json`~`005.json`, 실제 한국 자료의 파일 체크섬과 loader 결과를 직접 확인했다. 한국 자료는 **2010-01-04~2026-10-16** 삼성전자 4,126봉·SK하이닉스 4,124봉, KOSPI 벤치마크 4,126봉이다. 종목 결측/원본 OHLCV 오류 6개와 벤치마크 결측 2개를 별도 기록했으며 보간하지 않았다. 미국 SPY·S&P500 자료는 각 4,223봉이다. FRED 관측 환율 CSV는 2010-01-04~2026-10-09의 4,375행이며 공개시각·체결 가능 FX의 증거로 사용하지 않았다. 원본 시장 자료는 라이선스 때문에 GitHub에 재배포하지 않는다.

실제 한국 자료로 여섯 전략의 **기본 설정 엔진 통합 점검**을 독립 실행했고, 6개 모두 체결 원장 감사가 통과했다. A/B/C에서 각각 90/27/4개의 완결 거래, D/E/F에서는 필요한 재무/업종 입력 부재로 0개가 관측됐다. B는 사전 고점 손실 한도에 도달하여 중단됐다. 이 실행은 전기간 엔진 점검이며 개발 후보 선정·워크포워드·최종 독립 전략 성과와 구분한다. 그 결과로 전략·정책·파라미터를 수정하지 않았다. 단일 실행 시간은 A 5.469초, B 6.894초, C 15.612초, D 2.902초, E 2.991초, F 5.735초였다.

**전체 구간 엔진 통합 점검에 같은 자료를 사용했으므로, 이번 최종기간은 사람이 한 번도 보지 않은 엄격한 블라인드 독립 표본이라고 주장할 수 없다.** 자동 경로의 시계열 분리·사전 후보 고정은 별도로 검사했지만, 이후 실제 합격 판단에는 새로 확보한 미사용 기간이 필요하다. 현재 PIT 구성종목·기업행동 회계·공시 당시 재무/전망·업종 이력도 완전하지 않으므로 실제 일봉 수집·회계 감사 통과를 전략 합격으로 바꾸지 않는다.

수정 통합 후 세 번째 검토자가 `/workspace/.venvs/stock-validator/bin/python -m pytest -q`를 직접 실행한 결과는 **145개 통과, 실패 0, 건너뜀 0 (5.62초)**였다. 합성 수기 거래, 부당한 중간 순자산/미청산 목록/비정수 체결/NaN 위조 탐지, 과거 prefix 불변, 데이터 변조·경로·사후 선언 신뢰 거부, 정책 수치·시장 국면 검사, 미인증/환율 결측 차단, 최종기간 재개봉 방지와 현재 인증 무효화, 실제 HTTP 경계 검사가 포함된다. 실제 시장의 수익성 합격 테스트는 통과했다고 표시하지 않는다. 이후 루트 통합 실행의 최종 테스트 수·인증과 연구 결과는 `RESULTS.md`에 별도로 기록한다.

## 남은 제한

- 일봉 거래량 기반 체결 상한은 실제 시가 호가·장중 체결순서의 재현이 아니다. 손절·목표가는 시장가 트리거이며 갭·미체결로 계획손실을 초과할 수 있다.
- OHLCV 결측 세션은 명시적으로 보존하며 가격을 보간하거나 거래정지로 단정하지 않는다. 당시 보유분의 진짜 평가·장중 위험·누락 세션의 체결 결과를 알 수 없다.
- Yahoo의 사후 가격 조정, 배당·분할·상폐 회계, 완전한 과거 구성종목의 감사 수집기는 미완성이다. 미국 관측 환율은 실행 가능한 PIT 환율과 다르다.
- 정확히 동일한 원관측 자료의 재개봉은 로컬 레지스트리로 차단한다. 자료 개정·추가·종목 일부 변경 간 같은 최종기간의 계보 추적, 레지스트리 고의 삭제 방지는 구현되지 않았다.
- 비용률은 연구 가정이며 국가·날짜·계좌별 실제 세법/수수료표가 아니다. 독립 감사의 통과는 입력 가격이 사실이거나 미래에도 수익이 난다는 보증이 아니다.
- 기본 시장 필터와 하락장 거래 표본 기준의 불일치(S9)는 남아 있다. 하락장에 현금으로 대기하는 행동 자체를 실패로 단정할 수 없지만, 현재 거래 진입 국면별 집계만으로 그 방어 성과를 평가할 수 없다. 실행 뒤 기준을 바꿔 이번 결과를 합격시키지 않는다.
- 개별 체결·완결 거래 원장은 `BacktestResult.fills`/`trades` 메모리 객체에서 감사하지만 현재 JSON 보고서에는 모든 체결·거래 행을 내보내지 않는다. 보고서에는 집계·곡선·독립 감사 결과·미청산·거부 기록이 남는다. 외부 재감사 가능한 영속 원장 내보내기는 다음 개발 항목이다.
