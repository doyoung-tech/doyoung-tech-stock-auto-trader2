## 세 차례 독립 검토와 수정

1. [설계·데이터·논리 검토](review-1-design.md): 당일 종가 FX를 당일 시가에 쓰는 누출 위험을 차단했다. 메타데이터의 사용자 `true`만으로 PIT/기업행동을 인증하지 않는다. 종목별 보유일과 혼합 시장 purge를 점검했다.
2. [계산·체결·장애 검토](review-2-engine.md): 위험 고점과 성과 MDD 고점 혼용, 중간 자산곡선 위조를 놓치는 감사, 목표 주문 설명 불일치를 수정했다. 매 시점 원장 재구성과 수기 부분청산 회귀를 추가했다.
3. [실제 자료·성능·보안·전체 검토](review-3-system.md): JSON 비유한수·과도한 중첩·심볼릭 링크 노출, 화면의 허위 PASS 가능성, 인증 해시 누락, 정책 검증과 실제 보고서 필드 불일치를 수정했다. 원본 가격 오류는 격리하고 입력 사실로 인정하지 않았다.

마지막 검토에서는 **하락장 신규 진입을 막는 기본 시장 필터와 하락장 진입 거래 표본을 요구하는 기준의 충돌**도 확인했다. 현재 설정은 이 조건을 충족할 수 없다. 결과를 본 뒤 기준을 완화하지 않았고 미해결 설정 문제로 남겼다. 다음 연구는 새 미사용 자료를 보기 전에 현금/노출과 국면별 순자산 평가 또는 필터 후보를 일관되게 사전 등록해야 한다.

실제 한국 구간의 모든 실행 단계에서 별도 회계 감사가 통과했다. 같은 입력의 보고서 재표시는 새 최적화 없이 원본과 바이트 단위로 일치했다. 미국은 FX 결측 시 모든 전략의 성과가 빈 상태로 남는 것을 확인했다. 합성 데모의 3단계 기능도 실행했으며 합성 합격은 차단된다. 수기 예제·무작위 시나리오는 가상 데이터이고 시장 성과가 아니다.

Chromium에서 실제 보고서를 렌더링하고 360/390/768/1440px 폭, 여섯 카드, 기간/곡선, E 미실행 표시, 합격 없음, 가상/실제 경고, 주문 쓰기 405 거부를 확인했다. 별도 화면 검사에서는 375px도 확인했다. 설치 스크립트를 반복 실행해도 핀된 의존성·테스트 인증이 정상이다. 이는 공개 모바일 서비스 운영 검사나 미래 수익성 보증이 아니다.

초기 기본 Python의 pytest 부재, 작성 전 테스트 파일 지정으로 인한 실행 오류는 공유 가상환경과 파일 완성 뒤 해결했다. 최종에 실패한 자동 테스트는 없지만, 원본 오류 격리·Stooq 수집 실패·FX/PIT 자료 부족·설정 충돌·통계 및 비용 민감도 미달은 해결된 것으로 표시하지 않는다.

## 미구현·다음 개발 단계

1. 상장폐지 포함 PIT 구성종목·공시/정정·전망·업종/대형주 이력의 감사 수집과 분할·배당·종목코드 변경·상폐 현금흐름 회계를 우선 완성한다. 키가 필요하면 데이터 제공처용만 환경 설정에 안전하게 등록하고 실전 증권사 주문 키는 요구하지 않는다. 유료 계약은 승인 전 진행하지 않는다.
2. 시장 필터와 국면 평가의 충돌을 새 사전 정책에서 해결하고, 이전 자료/개발에 전혀 사용하지 않은 새 기간으로 검증한다. 데이터 개정 간 holdout 계보·중앙 연구 등록도 필요하다.
3. 날짜별 실제 세금/수수료표, 실행 가능한 환전 가격, 정식 거래소 달력, 시가 유동성·분봉 체결을 검증한다. 1/10/60분봉과 대규모 전 종목 성능은 미구현/미검증이다.
4. 현재 독립 감사는 메모리의 fills를 재구성한다. 보고서에 개별 체결/거래 원장 영속 내보내기는 미구현이다. 수수료 계산의 별도 독립 oracle도 추가할 수 있다. 현재는 수기 엔진 비용 테스트와 별도 회계 재구성을 조합한다.
5. 외부 모바일 접속을 위한 인증·호스팅·HTTPS 운영 배포는 별도 단계다. 현재 UI는 구현·로컬 검증됐고 공개 주소는 제공하지 않는다. 실전 주문은 이후 별도 범위이며 이번 저장소 버전에는 없다.

설치/시작 설정을 저장해도 환경 게시나 새 태스크 복원까지 검증한 것은 아니다. 환경 설정에서 변경 검토·저장 후 게시해야 한다.
