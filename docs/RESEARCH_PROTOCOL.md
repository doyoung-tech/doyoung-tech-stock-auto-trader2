# 실행 전 연구 규칙과 한계

합격 기준은 `config/acceptance.json`을 읽고 `acceptance.lock.json`에 전체 내용과 SHA-256을 먼저 저장한다. 모든 후보의 개발기간 선택을 마친 뒤 `selection.lock.json`을 저장한 후에만 최종 검증 구간을 엔진에 전달한다. 이 작업에서는 실제 결과를 보고 기준을 완화하지 않는다.

## 구간과 선택

- 앞 45% 개발, 다음 35%를 3개 순방향 워크포워드 구간, 마지막 20%를 최종 구간으로 나눈다.
- 종목별 관측 봉 수를 기준으로 최대 후보 보유기간만큼 경계에서 비운다. 포지션은 구간을 넘기지 않는다. 각 구간 안에서 지표를 준비하므로 경계 이전의 warm-up을 재사용하지 않는 보수적 구현이다.
- 개발 구간에서 수익률/낙폭 비율로 한 후보를 선택한다. 워크포워드·최종 구간에서는 그 후보를 다시 고르지 않는다. 워크포워드는 고정 전략을 반복 검증하는 방식이며 매 fold 재학습 모델이 아니다.
- 손절 3/4/5%, ATR 2/3배, 목표 방식, 부분익절 유무, 후행손절 유무, 최대 보유일과 신호 인접값을 사전에 정의한다. 고차원 전체 조합 탐색 대신 한 요소를 바꾼 후보군이다.
- E의 최대 1~5년 보유와 별도 표본 기준을 충족하지 못하면 해당 독립 검증은 미실행으로 남긴다. 짧은 자료에서 장기 수익을 외삽하지 않는다.

## 사전 합격 조건

정확한 수치는 정책 파일이 기준이다. 최종 비용 차감 수익성, 워크포워드 순실현손익, 반복 구간 수익 안정성, MDD, 충분한 거래 수, 상승/하락/횡보 국면별 기대손익, 적절한 벤치마크, 비용 2배, 인접 파라미터의 안정성을 검사한다. 샘플 부족·미청산 보유분·독립 감사 오류·환율/데이터 증거 부족은 데이터 부족이다. 성과·위험 기준 미달은 실패 원인에 별도 기록한다. 두 가지가 동시에 있으면 최종 상태는 데이터 부족이고 경제적 실패도 숨기지 않는다.

거래당 기대손익 구간은 같은 날짜의 청산을 묶은 순환 이동 블록 재표집으로 산출한다. 가까운 청산의 의존성을 근사하고 봉 보유기간을 반영한 블록 길이를 사용한다. 모든 사전 후보 수로 Bonferroni 보정을 적용하며 꼬리 해상도가 부족하면 통계 구간을 합격 근거로 쓰지 않는다. 정규분포 독립 표본이라고 가정하거나 미래 수익을 보장하지 않는다.

## 최종기간 재사용 통제

저장소 `.research_state/holdouts`에 같은 원주가 관측의 최종기간 개봉을 기록한다. 실행이 중단되어도 이미 개봉한 기간을 다른 코드·정책·시드로 다시 열지 않는다. 동일 실행의 완료 결과는 원본을 재계산하지 않고 재표시한다. 현재 테스트 인증이 무효이면 보관된 결과를 현재 인증된 결과로 표시하지 않는다.

이 장치는 로컬 연구 실수를 줄이기 위한 것이다. 파일을 고의 삭제하거나 원주가를 개정/추가한 자료 간 기간 중복을 전역으로 통제하지 못한다. 중앙 `study_id`, 불변 등록소, 데이터 버전 간 기간 계보 관리가 후속으로 필요하다.

## 이번 실제 자료의 독립성 제한

같은 한국 자료의 전체기간을 엔진 통합·독립 회계 감사 점검에도 사용했다. 자동 선정 경로의 시간분리는 테스트했지만 사람이 전혀 보지 않은 블라인드 최종 검증으로 주장하지 않는다. 기업행동·PIT 증거도 미완성이라 실제 전략은 모두 합격 불가다. 수익성 인정에는 새 미사용 기간, 정식 데이터 감사, 필요시 외부 독립 검토가 필요하다.
